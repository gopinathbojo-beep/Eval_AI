2. DETAILED DEFECT LOG (CATEGORIZED BY SEVERITY)
================================================================================

--------------------------------------------------------------------------------
[BUG-001] [SEVERITY: MEDIUM] [MODULE: EXAM WORKSPACE / REPORT CARDS ROUTING]
Summary: Route mismatch for class report card downloads produces HTTP 404 when 
         accessed from exam contexts.
Steps to Reproduce:
  1. Finalize an exam that has student evaluations.
  2. Attempt to fetch class report cards using `/api/exams/{exam_id}/report-cards`.
  3. Server responds with `HTTP 404 Not Found`.
Root Cause:
  The report card endpoint was implemented under `school.py` as:
    `GET /api/classes/{class_id}/report-cards?academic_year=...&exam_type=...`
  However, exam-level workspace navigation or legacy callers expecting 
  `/api/exams/{exam_id}/report-cards` receive 404.
Recommendation:
  Either add an endpoint redirect/proxy in `evaluations.py` or `school.py`:
  `GET /api/exams/{exam_id}/report-cards` that looks up the exam's `class_id`,
  `academic_year`, and `exam_type` and returns `build_report_cards()`, or ensure
  the frontend always routes through the class ID endpoint.

--------------------------------------------------------------------------------
[BUG-002] [SEVERITY: MEDIUM] [MODULE: PIPELINE & DOCUMENT PROCESSING]
Summary: Incomplete Question Paper uploads caused by service restart leave documents
         in FAILED state with manual reprocess needed.
Evidence:
  Live database inspection revealed:
  - Exam `17d5e75f-2439-4f7a-91bc-29d1036cd26a` (Page 1 AI_ERROR, Page 2 PENDING)
  - Exam `853508b3-8024-4485-83f8-24eaa83f9a94` (Page 1 OK, Page 2 PENDING)
  Error message stored: "Processing was interrupted by a server restart. Use Reprocess to continue."
Impact:
  Teachers uploading multi-page exam documents will see "AI Error / Needs Attention"
  if the background task worker restarts or times out, requiring manual button clicks.
Recommendation:
  Implement an automatic background recovery daemon at startup that queries for
  `QuestionPaperDocument.status == 'FAILED'` with restart flags and restarts processing
  transparently if the document has untouched pending pages.

--------------------------------------------------------------------------------
[BUG-003] [SEVERITY: LOW] [MODULE: RUN SCRIPTS / start.bat]
Summary: `start.bat` relies on Windows `netstat` and hardcoded port wait loops that
         can intermittently fail on systems with delayed port release.
Evidence from start.bat:
  `ping 127.0.0.1 -n 3 >nul` is used as an artificial 2-second sleep timer.
  `timeout /t 2 /nobreak >nul` fails under non-interactive shells or redirection.
Impact:
  If a service takes 3.5 seconds to bind (e.g. Vite cold start on HDD or Ollama warm-up),
  dependent scripts or immediate browser launches race against the opening port.
Recommendation:
  Replace the sleep ping with a native port-polling loop in PowerShell or Python, e.g.:
  `powershell -Command "while (!(Test-NetConnection -Port 8000).TcpTestSucceeded) { Start-Sleep 1 }"`

--------------------------------------------------------------------------------
[BUG-004] [SEVERITY: LOW] [MODULE: SECURITY / INPUT SANITIZATION]
Summary: Entity creation endpoints (`/api/classes`, `/api/subjects`, `/api/students`)
         do not strip raw HTML tags from input strings.
Evidence:
  Created a test class with name `<script>alert(1)</script>`.
  The backend stored the payload verbatim in `classes.name` with HTTP 201 Created.
Impact:
  While React automatically escapes strings in standard JSX renderers, raw PDF report 
  generators (ReportLab / PyMuPDF) or third-party Excel export readers could be exposed
  to script injection or markup breaking if raw strings are rendered in HTML templates.
Recommendation:
  Add a pydantic validator or `html.escape()` sanitization in `app/routes/core.py`
  to strip HTML special characters (`<`, `>`, `&`, `"`) on input.

--------------------------------------------------------------------------------
[BUG-005] [SEVERITY: INFORMATIONAL] [MODULE: BACKEND PERFORMANCE / TEST DURATION]
Summary: Top 3 longest-running test cases account for >15s of total 25s test suite execution.
Evidence:
  - `test_duplicate_mapping_and_ai_unavailable`: 5.79s
  - `test_full_workflow`: 5.48s
  - `test_bulk_sheets_are_matched_to_students_or_held`: 4.35s
Root Cause:
  Full workflow tests invoke multiple rounds of PDF generation (`fitz.open()`) and 
  synchronous database commits with multi-stage segmentation loops.
Recommendation:
  Use in-memory pre-generated binary mock fixtures for tests where PDF rendering
  is not the primary assertion target.
